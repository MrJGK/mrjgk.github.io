Making the network visible.

The Network Monitoring and Visualization System brings device discovery, availability checks, network-speed information, alerts, and network mapping into one planned monitoring platform. Its purpose is to make network status easier to understand and reduce the effort of observing devices manually.

The wider project includes authentication, scanning, monitoring, storage, reporting, and priority-based access control. The visual dashboard and topology map connect this information so users can understand both the status of a device and its place in the network.

Project scope and current implementation: the modules below describe the complete system design. My working contribution focuses on network topology; broader modules are part of the team’s integration scope.

Project objectives

  • Discover connected devices and organize their details in one place.
  • Show device relationships through an interactive network map.
  • Bring connectivity, performance, and alert information into a clear interface.
  • Retain monitoring history and support periodic reports.
  • Extend the system with access decisions based on device priority.

My contribution: network topology

I am developing the React topology module: the canvas, device interactions, data handling, and the interface around the map. The module is designed to fit into the assembled monitoring dashboard.

  • Interactive network map. Display routers, switches, computers, printers, and the connections between them using React Flow.
  • Automatic layout. Organize incoming device data into a readable topology.
  • Device search. Find a device by name, IP address, or type, with handling for an empty search.
  • Device details. Select a device to inspect its available information in a details panel.
  • Add-device form. Add a device through the interface and connect it to the designated switch in the topology.
  • Refresh controls. Refresh the topology and alerts together to update the interface.
  • Alerts panel. Display critical, warning, and information alerts when supplied by the data source.
  • Flexible data sources. Support mock data, raw backend data, and an API-backed integration path.
  • Scanner navigation. Provide an entry point for the scanning module when its route is connected during assembly.

The complete system: 11 modules

These modules form the project’s documented design. Technology names in this section describe the proposed stack for the broader system.

01

Login System

Authenticate users, support login and logout, and distinguish administrator and user roles before allowing access to the dashboard.

HTML · CSS · JavaScript · React · FastAPI · JWT

02

Network Scanner

Discover local network devices such as computers, routers, printers, and laptops. Collect device names, IP addresses, and MAC addresses where available.

Python · Nmap · Scapy

03

Device Monitoring

Check device availability and report online or offline status. Track response time and supported system-health information.

Python · ping3 · psutil · SNMP

04

Network Speed

Observe upload and download rates and bandwidth utilization to help identify periods of high network usage.

Python · psutil · Scapy

05

Dashboard

Present device counts, graphs, alerts, and overall network status in a centralized monitoring interface.

React · HTML · CSS · Tailwind CSS · Chart.js or Recharts

06

Network Map — my main module

Visualize routers, switches, and connected devices. Support an interactive topology with device search, details, layout, and data refresh.

React · React Flow · JavaScript · Vite

07

Alerts

Notify users when devices go offline or network problems are detected, helping make issues visible sooner.

FastAPI · WebSockets

08

Database

Store device information, monitoring history, alerts, and report data for later analysis.

PostgreSQL · SQLAlchemy

09

Reports

Generate daily, weekly, and monthly network summaries, with PDF export for documentation and analysis.

Python · Report generation

10

Testing & Documentation

Check individual modules and their integrations, fix issues, and prepare the project report and presentation.

GitHub · Postman · Project documentation

11

Priority-Based Network Access Control

Add access decisions based on device priority and configured network-use rules. This extension is being developed separately as a Python simulation.

Read the access-control project

How the system fits together

  1. Authenticate and discoverLog in, scan the network, and identify connected devices.
  2. Monitor and evaluateObserve device status and network speed, then evaluate the configured priority policy.
  3. Store monitoring informationRetain device records, monitoring history, and detected events.
  4. Visualize the networkPresent the current information through the dashboard and topology map.
  5. Surface issues and reportDisplay alerts and produce summaries for review and documentation.

This describes the intended integrated workflow. The topology module consumes the data made available by the backend.

One map. Multiple data sources.

The topology is being designed to work with a teammate’s backend. The integration supports direct data first and an API connection when an endpoint is available.

Data flow inside the frontend

  3. Arrange nodesThe layout layer determines useful positions for devices.
